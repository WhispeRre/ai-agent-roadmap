# 2026-07-29：托管 Agent 的运行时约束与安全调查 MCP

> 本页于北京时间 2026 年 7 月 29 日 03:20 核验。Google AI RSS 的最新条目发布于 7 月 28 日 16:00 UTC，AWS What's New 的最近相关条目发布于 7 月 28 日 10:00 UTC；本次未发现 7 月 29 日当天发布的 AI/Agent 正式公告。以下内容是截至今天最新可核验的 AI/Agent 动态。文中“发布时间”与“核验时间”分别标注，不将旧公告写成当天发布。

## 今日焦点：Gemini API Managed Agents 增加运行时治理能力

Google 于 **2026 年 7 月 28 日 16:00 UTC** 发布 *Gemini API Managed Agents: 3.6 Flash, hooks, and more*。官方文章称，Managed Agents 默认使用 Gemini 3.6 Flash；新增环境 hooks，可在远程沙箱内的每次工具调用前后运行自定义脚本，以阻断、检查或审计调用。此次更新还包含模型选择、免费层访问、总 token 预算上限和按 cron 调度的 triggers。

- [Google 官方文章：Gemini API Managed Agents: 3.6 Flash, hooks, and more](https://blog.google/innovation-and-ai/technology/developers-tools/expanding-managed-agents-gemini-api-3-6-flash-hooks/)
- [Google AI 官方 RSS](https://blog.google/innovation-and-ai/technology/ai/rss/)

官方文章还说明，Managed Agents 在隔离的云端沙箱中协调推理、代码执行、包安装、文件管理和网页检索。预算达到上限时，交互状态会以 `incomplete` 返回并保留环境状态，之后可用新预算继续；定时 trigger 会将 Agent、环境、提示词和 cron 计划绑定为持久资源。

### 已验证事实与限制

已验证事实仅包括上述官方文章明确列出的默认模型、hooks、预算控制、定时触发、免费层和远程沙箱行为。文章示例使用的是预览 Agent 标识，未构成所有模型、地区、账号层级或生产 SLA 的承诺；实际可用性、费用、网络策略和配额仍应以项目控制台与产品文档为准。

**对 Agent 开发的启示**：把 hooks 与预算当作运行时控制面，而不只是开发阶段的检查。至少为 `write_file`、代码执行、网络访问和外部副作用工具设置前置策略；同时记录每次触发的预算、停止原因、恢复次数和人工接管结果。定时任务还应配置幂等键与重复执行告警，避免“定时”扩大重复副作用。

## 安全工作流：AWS 将 Exposure Findings 接入本地 MCP App

AWS 于 **2026 年 7 月 27 日 17:00 UTC** 发布 *AWS Security Hub MCP App brings exposure findings into your AI-assisted workflow (Preview)*。公告称，这是一个在本机运行的 MCP server，可使用既有 AWS 凭证把 Security Hub 的 exposure findings 提供给 Claude Desktop。官方列举的能力包括：以自然语言查看重点暴露项、查看 attack path 与 expanded network path、检查关联 findings 和受影响资源配置，以及取得修复建议。

- [AWS 官方公告：AWS Security Hub MCP App brings exposure findings into your AI-assisted workflow (Preview)](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-security-hub-mcp-app/)
- [AWS What's New 官方 feed](https://aws.amazon.com/about-aws/whats-new/recent/feed/)

AWS 明确标注该能力为 **Preview**，在支持 Security Hub 的 AWS 商业区域提供；每次工具调用会返回给 AI Agent 推理的文本摘要以及供人在同一对话中核验的交互式可视化。公告也明确该 MCP server 的工具为只读，不会修改环境。

### 已验证事实与限制

“只读”只描述该公告中 MCP App 工具的行为，不能自动覆盖 Claude Desktop、本机凭证策略、日志保留或其他已连接工具。修复建议也不等于已完成修复；Preview 功能的范围与可用性可能变化。

**对 Agent 开发的启示**：优先让安全 Agent 从只读调查开始，并把“建议”和“执行”拆成不同权限阶段。对每个 finding 保存来源、查询时间、证据链接、建议动作、审批人和实际变更记录；在批准前禁止 Agent 写入 IAM、网络和生产配置。这样能保持调查可追溯，也不会把模型的摘要误当成最终安全结论。

## 近期基础设施进展：DataSync 扩展受管迁移 Agent 的接入范围

AWS 于 **2026 年 7 月 28 日 10:00 UTC** 发布 *AWS DataSync Enhanced mode adds HDFS, Azure Blob, and object storage locations with Hyper-V agent support*。这不是 LLM Agent 产品公告，但它展示了受管迁移 Agent 的运营边界：Enhanced mode 支持通过 Agent 在 HDFS、Microsoft Azure Blob Storage 和自管对象存储之间传输数据，也支持在 Microsoft Hyper-V 部署 Agent。AWS 同时称其提供并行传输、不限文件数和详细指标。

- [AWS 官方公告：AWS DataSync Enhanced mode adds HDFS, Azure Blob, and object storage locations with Hyper-V agent support](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-datasync-hdfs-azure-blob-hyper-v/)

这项能力在提供 AWS DataSync 的区域可用。对涉及知识库或大规模数据准备的 Agent 系统而言，迁移层的可观测性、认证与数据加密同样是上线前置条件；它并不意味着数据可被模型或 Agent 自动访问。

## 可以立即实践的内容

为现有 Agent 的每个高风险工具补一条运行时策略，并把自动执行与人工批准分开记录：

```text
tool_name:
side_effect: read_only | reversible_write | irreversible_write
pre_hook_policy:
post_hook_audit:
max_total_tokens:
schedule_and_idempotency_key:
evidence_links:
human_approval_required:
resume_conditions:
```

先只覆盖读取安全发现、写文件、执行命令和网络访问四类工具。连续运行一周后，审查被阻断调用、预算耗尽、恢复执行和人工批准的比例，再决定是否给任何外部写入权限。
