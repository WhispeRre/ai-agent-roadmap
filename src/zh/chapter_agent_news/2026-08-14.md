## OpenAI：GPT-5.6 将长任务能力拆成可组合的 Agent 原语

OpenAI 于 **2026 年 8 月 13 日**发布 *The builder’s guide to GPT-5.6*，面向在生产环境构建 Agent 的团队。文章把 GPT-5.6 的价值概括为更高的 Agent 性能和更低成本，并强调应通过模型选择与 API 控制共同设计工作流，而不是只把所有步骤交给最高规格模型。

- [OpenAI 原始文章：The builder’s guide to GPT-5.6](https://openai.com/index/builders-guide-to-gpt-5-6/)

文章点名了三类 Responses API 能力：跨轮次保留 reasoning、用 native compaction 压缩长对话、用 native multi-agent orchestration 并行拆分任务；另可用 programmatic tool calling 在模型上下文之外过滤、聚合和编排工具输出。文中一个 ARC-AGI-3 示例称，启用保留推理与压缩后，GPT-5.6 Sol 得分从 **13.3%** 升到 **38.3%**，输出 token 约减少 6 倍。这是 OpenAI 在特定基准与 harness 下的报告，不能直接当作所有业务流程的收益保证。

## 工程含义：让“记忆、并行、确定性处理”各自有边界

这组原语适合映射到清晰的运行时责任：

- **持久推理与压缩**：保存跨轮次的必要状态，同时设置压缩触发条件、摘要校验和上下文丢失告警；不要把未经验证的模型摘要当作事实数据库。
- **多 Agent 编排**：为每个子 Agent 固定输入、工具权限、预算和输出 schema；聚合器只接收必要字段，并记录失败、超时与重试原因。
- **程序化工具调用**：将排序、去重、阈值判断等确定性逻辑移到代码，模型保留规划和判断；对外发消息、写入生产系统等副作用动作仍需审批或可撤销路径。
