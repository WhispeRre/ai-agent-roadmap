# 2026-07-25：长时程 Agent、模型分层与云端推理

> 本页截至北京时间 2026 年 7 月 25 日整理。当前核验到的最新官方公告发布于 7 月 24 日；截至整理时，所检查的 OpenAI、Anthropic、Google 与 AWS 官方页面尚未出现 7 月 25 日的新公告。

## 今日焦点：Claude Opus 5 面向长时程 Agent 发布

Anthropic 于 7 月 24 日发布 Claude Opus 5，强调它在编码、知识工作、计算机操作和长时程任务中的表现。模型已在 Claude API、Claude.ai、Claude Code 和 Claude Cowork 等平台提供，API 模型名为 `claude-opus-5`，定价为每百万输入 token 5 美元、输出 token 25 美元，与 Opus 4.8 相同。

Anthropic 称 Opus 5 更擅长先验证、再迭代，尤其适合需要多轮工具调用和自我检查的 Agent。官方列出的能力信号包括：

- 在 Frontier-Bench、CursorBench、AutomationBench 和 OSWorld 2.0 等评测中，Opus 5 在成本与完成质量之间取得更好的平衡。
- 支持不同 effort 档位，开发者可以按任务风险、时延和预算调整推理强度。
- 新增对话中途变更工具的 beta 能力；变更可用工具时不会使提示缓存失效。
- API 提供自动回退 beta：当安全分类器拦截 Opus 5 请求时，可以按配置路由到其他模型。

- [Anthropic 官方公告：Introducing Claude Opus 5](https://www.anthropic.com/news/claude-opus-5)
- [Claude Opus 5 System Card](https://www.anthropic.com/claude-opus-5-system-card)

### 厂商结论与已知限制

上述性能数字和早期客户案例主要来自 Anthropic、自建评测或合作方反馈，不等于独立验证。Anthropic 也明确说明，Opus 5 在网络安全任务上仍落后于 Mythos 5，长时间自主开展生物研究仍有重要限制。

安全机制同样会改变 Agent 的实际行为：部分网络安全请求会被分类器拦截，Claude 产品中的受限请求默认可能回退到 Opus 4.8。因此，生产评测不能只记录最终答案，还应记录实际使用的模型、回退原因、工具轨迹和中间失败。

**对 Agent 开发的启示**：长时程能力不只是“让模型运行更久”。工程上需要为任务设定阶段检查点、最大工具调用次数、可恢复状态、人工接管条件，以及模型回退后的结果一致性测试。

## 平台进展：GPT-5.6 全系列接入 Amazon Bedrock

AWS 于 7 月 24 日宣布 OpenAI GPT-5.6 Sol、Terra 和 Luna 在 Amazon Bedrock 正式可用，并提供与 OpenAI Responses API 兼容的 `bedrock-mantle` 入口。三个型号对应不同工作负载：

| 型号 | 官方定位 | 典型 Agent 场景 |
| --- | --- | --- |
| Sol | 旗舰推理模型 | 自主编码、安全研究、科学分析、深度多步推理 |
| Terra | 性能与成本平衡 | 通用生产任务、日常工具调用与业务流程 |
| Luna | 低成本、低时延 | 分类、摘要、路由和高吞吐前置处理 |

三个型号均支持文本和图片输入、文本输出、272K token 上下文、工具调用，以及从 `none` 到 `max` 的推理强度配置。AWS 还给出了 Codex 接入方式：在配置中把模型提供方设为 Amazon Bedrock，即可通过 AWS 账户、区域处理与权限体系运行 GPT-5.6。

- [AWS 官方指南：Get started with OpenAI GPT-5.6 Sol, Terra, and Luna on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/get-started-with-openai-gpt-5-6-sol-terra-and-luna-on-amazon-bedrock/)

### 生产部署需要同时核对的边界

- **数据处理**：AWS 表示提示与输出不会用于训练模型，也不会默认共享给模型提供方；但被分类器标记的流量可能由 AWS 保留最多 30 天用于离线滥用检测。
- **区域可用性**：Sol、Terra 和 Luna 支持的 AWS 区域并不完全相同，迁移前需要核对数据驻留和故障切换方案。
- **缓存成本**：缓存读取相对未缓存输入有 90% 折扣，但缓存写入按未缓存输入价格的 1.25 倍计费，不能只看命中时的低价。
- **配额与重试**：配额按模型和区域的输入、输出 token 速率计算。遇到 HTTP 429 时应使用有上限的指数退避，而不是无限重试。

**对 Agent 开发的启示**：兼容同一套 API 并不代表运行语义完全相同。身份认证、数据保留、模型 ID、区域、缓存、配额和错误码都应作为 provider adapter 的显式配置，并纳入集成测试。

## 生态信号：模型发布正在同步进入云平台

AWS 同日发布 Claude Opus 5 在 Amazon Bedrock 的集成说明，重点面向 Agent 系统与生产推理负载。这与 GPT-5.6 的 Bedrock 接入共同说明，前沿模型竞争正从单一厂商 API 扩展到云平台中的统一采购、权限、审计和区域部署。

- [AWS 官方指南：Introducing Claude Opus 5 on AWS](https://aws.amazon.com/blogs/machine-learning/introducing-claude-opus-5-on-aws-anthropics-most-capable-opus-model/)

这类平台接入可以降低迁移和治理成本，但也会增加一层平台差异。评估时应分别测量模型能力和托管平台行为，避免把区域限制、网关错误或平台侧安全策略误判为模型能力问题。

## 今日趋势判断

| 方向 | 最新信号 | 工程要求 |
| --- | --- | --- |
| Agent 任务时程继续拉长 | Opus 5 强调验证、迭代与长任务能力 | 检查点、预算上限、可恢复状态、人工接管 |
| 模型形成稳定能力分层 | GPT-5.6 以 Sol、Terra、Luna 覆盖不同成本与时延 | 动态路由、统一评测、按任务风险选型 |
| 前沿模型进入统一云平台 | GPT-5.6 与 Opus 5 同日进入 Bedrock | Provider 抽象、区域治理、审计与数据保留核验 |
| 推理优化进入系统设计 | effort、缓存和配额都能改变成本与结果 | 记录实际模型、缓存命中、token 速率与回退轨迹 |

## 可以立即实践的内容

为现有 Agent 增加一份“运行清单”，每次执行至少记录：

```text
任务 ID / 阶段
  -> 请求的模型、实际模型与 provider
  -> reasoning effort 与 token 预算
  -> 工具调用次数、失败次数与最后检查点
  -> 缓存读取、缓存写入与总输入 token
  -> 安全拦截、模型回退与人工接管原因
  -> 区域、时延、错误码与重试次数
```

然后用同一组长任务分别测试高性能模型和经济型模型。不要只比较最终答案，还要比较完成率、总成本、工具错误恢复能力，以及发生回退后结果是否仍满足验收条件。
