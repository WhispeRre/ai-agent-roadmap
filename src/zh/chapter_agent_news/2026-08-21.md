# 2026-08-21：隐私安全、沙盒治理与可验证输出

> 本页于北京时间 **2026 年 8 月 21 日 03:51** 核验。截至核验时，未发现可直接复验为 8 月 20 日或 8 月 21 日发布的官方 AI/Agent 公告；以下为“截至今天最新可核验的 AI/Agent 动态”。各条目的原始发布时间单独列出，不把较早公告写成今日发布。

## OpenAI：在零数据保留下扩展跨交互安全信号

OpenAI 于 **2026 年 8 月 19 日**发布 *Offering Zero Data Retention for frontier models*，预览 Private Safety Processing。公告重申，符合条件的 API 客户使用 Zero Data Retention（ZDR）时，提示词和模型响应在请求处理后不会由 OpenAI 保留；企业数据除非明确选择加入，也不会用于训练模型。

- [OpenAI 官方原始公告：Offering Zero Data Retention for frontier models](https://openai.com/index/offering-zero-data-retention-for-frontier-models/)

公告指出，单次交互审查可能看不到长任务中的风险，因此 Private Safety Processing 会在相关交互之间识别模式，同时让客户内容留在客户控制的基础设施，或使用客户控制密钥加密的 OpenAI 存储。OpenAI 人员默认只收到有限的风险信号，不接触底层提示词和响应；该方案仍在早期客户中测试，技术白皮书计划于 9 月分享。

对 Agent 来说，隐私承诺与安全监控不必被设计成二选一，但必须把数据驻留、密钥控制、可见信号和申诉流程写成明确的运行契约。长任务还应记录跨交互关联的范围、停止后的行为和客户侧可复核的告警证据，避免“看不到内容”被误解为“无法治理风险”。

## Google：Managed Agents 用环境钩子把工具调用纳入沙盒策略

Google 于 **2026 年 7 月 28 日**发布 *Gemini API Managed Agents: 3.6 Flash, hooks, and more*。公告称，Gemini API 的 Managed Agents 默认使用 Gemini 3.6 Flash，并增加 environment hooks、预算控制、定时触发器和免费层访问。

- [Google 官方原始公告：Gemini API Managed Agents: 3.6 Flash, hooks, and more](https://blog.google/innovation-and-ai/technology/developers-tools/expanding-managed-agents-gemini-api-3-6-flash-hooks/)

Managed Agents 在隔离的云端沙盒中协调推理、代码执行、包安装、文件管理和网页检索。环境钩子可在每次工具调用前后运行自定义脚本：例如在 `pre_tool_execution` 阶段阻止 `code_execution` 或 `write_file`，在 `post_tool_execution` 阶段执行自动检查；钩子返回拒绝决定时，工具调用会被跳过，原因会回传给模型上下文。公告还说明，钩子支持 HTTP 处理器，失败语义和完整定义以开发者文档为准。

这为 Agent 运行时提供了一个清晰的策略插入点：把权限检查、格式校验、审计和预算门槛放在工具边界，而不是只依赖提示词。生产实现应为每个钩子记录匹配规则、输入摘要、决定、超时、失败处理和最终副作用，并限制 HTTP 钩子能访问的网络与凭据范围。

## Anthropic：Claude 文本水印强调溯源概率而非作者证明

Anthropic 于 **2026 年 8 月 14 日**发布 *How Claude’s text watermark works*。公告称，未来 Claude 模型生成的文本会包含水印，用于判断 Claude 参与生成的可能性；该方案面向全球推出，原因之一是遵循欧盟 AI 法案及相关透明度规范。

- [Anthropic 官方原始公告：How Claude’s text watermark works](https://www.anthropic.com/news/claude-text-watermark)

Anthropic 解释，水印利用低风险的词语选择，在不增加 token、不改变读者可感知的质量和内容的前提下留下可检测模式；它不包含用户、组织或聊天的识别信息。水印检测对短文本、事实性强的段落和只做轻量校对的内容较弱，能回答的是“Claude 可能参与了什么程度”，不能证明文本一定由 Claude 独立创作。未来 Claude 模型的水印检测 API 仍在规划中。

对内容型 Agent，溯源信号应作为证据链的一部分，而不是把检测结果当作作者身份或责任归属的唯一判断。保存生成模型、版本、提示来源、人工编辑和文件级 C2PA 凭证，并在 UI 与审计记录中区分“模型参与概率”“人类编辑”和“法律作者/责任”，能降低误判和过度归因。
